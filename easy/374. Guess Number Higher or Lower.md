# [374. Guess Number Higher or Lower](https://leetcode.com/problems/guess-number-higher-or-lower/description/?envType=study-plan-v2&envId=leetcode-75)

## Intuition

Find the correct number between `1` and `n` using the `guess()` API, which indicates whether the current guess is higher or lower than the correct answer.

The search space is ordered, and `guess()` tells us which half of the range can be eliminated, so we can apply **Binary Search**.

---

## Approach

1. Initialize the search range with `start = 1` and `end = n`.
2. While `start` is less than or equal to `end`, calculate `mid = start + (end - start) / 2` and use it as the current guess.
3. Based on the return value of `guess(mid)`, narrow down the search range.
   - If it returns `0`, we have found the correct answer, so return `mid` and terminate.
   - If it returns `1`, the correct answer is greater than `mid`, so update the range with `start = mid + 1`.
   - If it returns `-1`, the correct answer is less than `mid`, so update the range with `end = mid - 1`.
4. Repeat the process, reducing the search range by half each time until the correct answer is found.

---

## Complexity
### Time Complexity
**O(log n)** — The search range is reduced by half in each iteration.

### Space Complexity
**O(1)** — Only a few variables are used without any additional data structures.

---

## My Solution
```
public class Solution extends GuessGame {
    public int guessNumber(int n) {
        int start = 1, end = n;
        while (start <= end) {
            int mid = start + (end - start) / 2;
            if (guess(mid) == 0) return mid;
            else if (guess(mid) == 1) start = mid + 1;
            else end = mid - 1;
        }
        return 0;
    }
}
```

---

## Review

The Binary Search logic is correct, but there are few improvements to make.


### 1. Avoid Duplicate `guess(mid)` Calls

Store the result of `guess(mid)` in a variable to avoid calling it multiple times.

### 2. Use a Clearer Return Value

Return `-1` instead of `0` when the answer is not found, since 0 indicates a correct guess.

### 3. Variable Naming (Optional)

Use `low` and `high` (or `left` and `right`) instead of `start` and `end` for clearer Binary Search naming.


---

## Revised Solution
```
public class Solution extends GuessGame {
    public int guessNumber(int n) {
        int low = 1, high = n;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            int result = guess(mid);
            if (result == 0) return mid;
            else if (result == 1) low = mid + 1;
            else high = mid - 1;
        }
        return -1;
    }
}
```

## Performance Comparison

The revised solution may use slightly more memory.

The only difference is that we added one `int` variable:

```
int result = guess(mid);
```

This adds only a single `int` variable to the stack. Since the original code already uses variables such as `start` (or `low`), `end` (or `high`), and `mid`, adding one more `int` has no impact on the overall space complexity. Both solutions still have **O(1) space complexity**.

On the other hand, the original code is less efficient in terms of execution cost.

```
if (guess(mid) == 0) return mid;
else if (guess(mid) == 1) start = mid + 1;
else end = mid - 1;
```

Since `guess()` is a function call, calling it repeatedly introduces unnecessary overhead.

In the worst case, the original code calls `guess()` twice in a single iteration, while the revised solution calls it only once and reuses the result.

Therefore, the revised solution uses a negligible amount of additional memory in exchange for eliminating redundant function calls.
