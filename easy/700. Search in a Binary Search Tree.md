# [700. Search in a Binary Search Tree](https://leetcode.com/problems/search-in-a-binary-search-tree/description/?envType=study-plan-v2&envId=leetcode-75)

## Intuition

Use **DFS** to search the tree until a node with the same value as `val` is found.

If `root.val == val`, return the current `root`. If no matching node is found, return `null`.

---

## Approach

1. Traverse the tree using DFS to find a node where `root.val == val`.
2. Return the `TreeNode` if the value is found.
3. Return `null` if the value cannot be found.

---

## Complexity
### Time Complexity
**O(n)** — In the worst case, all nodes may need to be visited.

### Space Complexity
**O(h)** — The recursive call stack uses space proportional to the height of the tree.
For a balanced tree, this is `O(log N)`, while for a skewed tree, it can be `O(N)`.

---

## My Solution
```
class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        List<TreeNode> list = new ArrayList<>();

        dfs(root, val, list);

        return list.isEmpty() ? null : list.get(0);
    }

    private void dfs(TreeNode root, int val, List<TreeNode> list) {
        if (root == null) return;

        if (root.val == val) {
            list.add(root);
            return;
        }

        dfs(root.left, val, list);
        dfs(root.right, val, list);
    }
}
```

---

## Review

This approach uses DFS to search the tree until it finds a node where `root.val == val`.

Although the search returns immediately when the value is found, it does not take advantage of the ordering property of a BST.

A BST follows this rule:
> **Values in the left subtree < Current node value < Values in the right subtree**

Therefore, by comparing `val` with `root.val`, we can determine which direction to search.

- `val < root.val` → Search the left subtree
- `val > root.val` → Search the right subtree
- `val == root.val` → Return the current node

There is also no need to store the result in a `List` and retrieve it later. We can simply return the `TreeNode` as soon as we find it.

---

## Revised Solution
```
class Solution {
    public TreeNode searchBST(TreeNode root, int val) {
        if (root == null || root.val == val) {
            return root;
        }

        return val < root.val ? searchBST(root.left, val) : searchBST(root.right, val);
    }
}
```

### Comparison Summary

| | Before | After | 
| ------------------------ | ------------------------- | ------------------------------------|
| Auxiliary Data Structure | Requires `List<TreeNode>` | Not required                         |
| Helper Method (`dfs`)    | Separate method           | Not required                         |
| Search Direction         | Searches both subtrees    | Searches one side based on BST rules |
| Time Complexity          | `O(N)` in the worst case  | `O(H)`                               |

The key improvement is **using the BST's ordering property to reduce the search range.**

The original solution may explore both subtrees, while the improved version compares `val` with `root.val` and searches only the relevant subtree.

In addition, the `List<TreeNode>` and separate `dfs` method are removed, allowing the method to return the result directly.

### Key Improvements
- **Reduced Search Range by Leveraging BST Properties**
  - The original solution recursively searches both the left and right subtrees when the target value is not found at the current node.
  - The improved version uses the BST property `left < parent < right` to compare `val` with `root.val` and search in only one direction.
  - → The worst-case time complexity remains `O(N)`, but for a balanced BST, the search can be performed in `O(log N)` time.
- **Removed the Unnecessary Auxiliary Data Structure**
  - The original solution stores the found node in a `List<TreeNode>` and retrieves it later using `list.get(0)`.
  - The improved version returns the `TreeNode` immediately when it is found, eliminating the need to create and access a list.
  - → This simplifies the code structure and removes unnecessary object creation and data structure access.
- **Simplified the Search and Return Logic**
  - The original solution uses a separate `dfs` method and a `List` to pass the search result back to the caller.
  - The improved version immediately returns `root` when `root == null` or `root.val == val`. Otherwise, it recursively searches either the left or right subtree based on the BST property.
  - → The search and result-returning logic are handled within a single method, making the code easier to read and understand.
