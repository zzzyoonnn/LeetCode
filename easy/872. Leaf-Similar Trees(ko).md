# [872. Leaf-Similar Trees](https://leetcode.com/problems/leaf-similar-trees/description/?envType=study-plan-v2&envId=leetcode-75)

## Intuition

주어진 두 개의 이진 트리가 **leaf-similar**한지 확인해야 한다.

두 트리의 leaf node를 **왼쪽에서 오른쪽 순서로 탐색했을 때 같은 순서와 값을 가지는지** 비교하면 된다.

이를 위해 각 이진 트리를 DFS로 순회하면서 자식 노드가 없는 leaf node를 리스트에 저장한다. 두 트리의 탐색이 모두 끝난 후, 생성된 두 리스트를 비교하여 결과를 반환한다.

---

## Approach

1. 주어진 두 개의 이진 트리에 **DFS**를 적용한다.
2. 각 노드가 leaf node라면 해당 노드의 값을 리스트에 추가한다.
3. 두 트리의 탐색이 모두 끝나면 생성된 두 리스트를 비교한다.
4. 두 리스트가 동일하면 `true`, 그렇지 않으면 `false를 반환한다.

---

## Complexity
### Time Complexity
**O(n + m)** — 각 트리의 모든 노드를 한 번씩 방문한다. `n`과 `m`은 각각 두 이진트리의 노드 개수이다.

### Space Complexity
**O(n + m)** — 각 트리의 leaf node를 저장하기 위한 리스트가 필요하며, DFS 재귀 호출에 사용되는 스택 공간도 필요하다.

---

## My Solution
```
class Solution {
    public boolean leafSimilar(TreeNode root1, TreeNode root2) {
        Deque<Integer> list1 = new ArrayDeque<>();
        Deque<Integer> list2 = new ArrayDeque<>();

        dfs(root1, list1);
        dfs(root2, list2);

        return new ArrayList<>(list1).equals(new ArrayList<>(list2));
    }

    private void dfs(TreeNode root, Deque<Integer> list) {
        if (root == null) return;

        if (root.left == null && root.right == null) {
            list.offer(root.val);
            return;
        }

        dfs(root.left, list);
        dfs(root.right, list);
    }
}
```

---

## Review

기존 코드는 `ArrayDeque`에 leaf 값을 저장한 뒤, 비교하는 시점에 다시 `ArrayList`로 변환하고 있다.

```
return new ArrayList<>(list1).equals(new ArrayList<>(list2));
```

`ArrayDeque`를 사용하는 이유가 단순히 데이터를 추가하기 위한 것이라면, 굳이 `ArrayList`로 다시 변환할 필요가 없다.

처음부터 `ArrayList`를 사용하면 별도의 자료구조 변환 없이 `add()`로 값을 추가하고, 마지막에 `equals()`를 통해 두 리스트를 바로 비교할 수 있다.

즉, **알고리즘의 핵심적인 구조는 그대로 유지하면서 문제에 맞는 자료구조를 선택해 불필요한 변환을 제거할 수 있다.**


### Improvement Points

#### ArrayList
- 기존 코드는 `ArrayDeque`에 leaf 값을 저장한 후 `ArrayList`로 다시 변환한다.
- 처음부터 `ArrayList`를 사용하면 불필요한 변환과 복사를 제거할 수 있다.
- 기존의 "**두 트리의 leaf를 모두 수집한 후 비교한다**"는 구조는 그대로 유지하면서 코드를 단순화할 수 있다.

#### Stack
- 두 트리를 동시에 순회하며 leaf를 발견할 때마다 비교하면, 값이 다른 순간 바로 `false`를 반환할 수 있다.
- 재귀 대신 명시적인 Stack을 사용해 깊은 트리에서 발생할 수 있는 Stack Overflow 위험을 줄일 수 있다.
- 모든 leaf 값을 저장하지 않고 순회에 필요한 노드만 Stack에 유지할 수 있다.

## Revised Solution

## Ver1. ArrayList

기존 코드의 전체적인 알고리즘은 유지하면서 ArrayDeque를 ArrayList로 변경했다.

```
class Solution {
    public boolean leafSimilar(TreeNode root1, TreeNode root2) {
        List<Integer> list1 = new ArrayList<>();
        List<Integer> list2 = new ArrayList<>();

        dfs(root1, list1);
        dfs(root2, list2);

        return list1.equals(list2);
    }

    private void dfs(TreeNode root, List<Integer> list) {
        if (root == null) return;

        if (root.left == null && root.right == null) {
            list.add(root.val);
            return;
        }

        dfs(root.left, list);
        dfs(root.right, list);
    }
}
```


## Ver2. Stack

두 트리를 동시에 DFS로 순회하면서 leaf node를 발견할 때마다 값을 비교한다.

두 leaf 값이 다른 경우 즉시 `false`를 반환할 수 있다.

```
class Solution {
    public boolean leafSimilar(TreeNode root1, TreeNode root2) {
        Deque<TreeNode> stack1 = new ArrayDeque<>();
        Deque<TreeNode> stack2 = new ArrayDeque<>();

        if (root1 != null) stack1.push(root1);
        if (root2 != null) stack2.push(root2);

        while (!stack1.isEmpty() && !stack2.isEmpty()) {
            int leaf1 = nextLeaf(stack1);
            int leaf2 = nextLeaf(stack2);

            if (leaf1 != leaf2) return false;
        }

        return stack1.isEmpty() && stack2.isEmpty();
    }

    private int nextLeaf(Deque<TreeNode> stack) {
        while (!stack.isEmpty()) {
            TreeNode node = stack.pop();

            if (node.right != null) stack.push(node.right);
            if (node.left != null) stack.push(node.left);

            if (node.left == null && node.right == null) {
                return node.val;
            }
        }

        return -1;
    }
}
```

`nextLeaf()`에서 `right`를 먼저 push하고 `left`를 나중에 push하는 이유는 Stack이 **LIFO(Last-In, First-Out)** 방식으로 동작하기 때문이다. 따라서 `left`가 먼저 pop되어 DFS의 왼쪽 → 오른쪽 탐색 순서를 유지할 수 있다.

## 비교 요약

| 항목 | 기존 코드 | ArrayList 버전 | Stack 버전 |
| --- | --- | --- | --- |
| 자료구조 | `ArrayDeque` → `ArrayList` 변환 | `ArrayList` | `Deque`를 Stack으로 사용 |
| 구현 방식 | 재귀 DFS | 재귀 DFS | 반복문 + DFS |
| Leaf 비교 시점 | 전체 순회 후 비교 | 전체 순회 후 비교 | Leaf 발견 시 즉시 비교 |
| 조기 종료 | ❌ | ❌ | ✅ |
| 재귀 호출 | 사용 | 사용 | 사용하지 않음 |
| Stack Overflow 위험 | 있음 | 있음 | 없음 |
| Leaf 저장 | 전체 leaf 저장 | 전체 leaf 저장 | 별도 leaf 리스트 없음 |
| 코드 가독성 | 간결하지만 불필요한 변환 존재 | 가장 직관적 | 상대적으로 복잡 |
| 주요 장점 | 구현이 간단함 | 불필요한 변환 제거 | 조기 종료 및 추가 리스트 제거 |

코드의 간결성과 가독성을 고려하면 `ArrayList` 버전이 가장 직관적이다.
반면 Stack 버전은 두 트리를 동시에 순회하면서 leaf를 즉시 비교하기 때문에, 값이 다른 경우 조기에 탐색을 종료할 수 있다는 장점이 있다.

### Key Improvements(ArrayList 기준)
- **불필요한 자료구조 변환 제거**
  - 기존에는 `ArrayDeque`에 leaf 값을 저장한 후, 비교를 위해 다시 `ArrayList`로 변환했다.
  - `ArrayList`를 처음부터 사용하여 불필요한 복사와 자료구조 변환을 제거했다.

- **자료구조 사용 단순화**
  - 기존 코드에서는 leaf 값을 추가하는 용도로만 `ArrayDeque`를 사용하고 있었다.
  - 실제로 필요한 연산은 값 추가와 두 리스트의 비교이므로, `ArrayList`를 직접 사용하는 것이 더 적절하다.
  - → 문제에서 필요한 연산에 맞는 자료구조를 선택하여 코드의 구조를 단순화

- **실행 효율 개선**
  - 두 트리의 모든 노드를 순회해야 하므로 전체 시간복잡도는 여전히 **O(n + m)**으로 동일하다.
  - 하지만 `ArrayDeque`를 `ArrayList`로 변환하는 과정에서 발생하는 불필요한 복사 작업을 제거할 수 있다.
  - → 동일한 알고리즘 복잡도를 유지하면서 불필요한 작업 제거

- **코드 가독성 향상**
  - `ArrayDeque → ArrayList`로 변환하는 중간 과정을 제거했다.
  - → **leaf 값 수집 → 두 리스트 비교**라는 코드의 의도가 더 명확해짐

## LinkedList가 아닌 ArrayList를 사용한 이유

### 왜 LinkedList가 딱히 유리하지 않은가
이 코드에서 리스트에 수행하는 연산은 크게 두 가지다.

- leaf 값을 리스트의 끝에 추가(list.add(root.val))
- 두 리스트의 전체 값을 순차적으로 비교(list1.equals(list2))

### 끝에 추가하는 연산 (add)
- ArrayList: 평균적으로 **O(1)** 의 시간복잡도로 끝에 값을 추가한다.
- LinkedList: 마지막 노드에 대한 참조를 통해 **O(1)** 의 시간복잡도로 값을 추가할 수 있다.

이 연산만 놓고 보면 두 자료구조의 차이는 크지 않다. 

### equals() 비교
- ArrayList.equals(): 배열 기반으로 데이터를 연속적으로 저장하기 때문에 순차적인 데이터 접근에 유리하다.
- LinkedList.equals(): 각 노드가 서로 다른 메모리 위치에 존재할 수 있어, 노드를 따라가며 데이터를 접근해야 한다.

두 리스트의 값을 순차적으로 비교하는 이 문제에서는 `ArrayList`가 더 적합하다.

### 메모리 오버헤드
- LinkedList: 각 요소를 별도의 노드로 관리하며, 각 노드마다 다음 노드와 이전 노드를 가리키는 참조를 추가로 저장한다.
- ArrayList: 내부 배열에 요소를 저장하기 때문에 상대적으로 메모리 오버헤드가 적다.

### 결론
이 문제처럼 **끝에 값을 추가하고, 이후 전체 데이터를 순차적으로 비교하는 경우에는 `LinkedList`를 사용할 이유가 크지 않다.**

`ArrayList`는 이 문제에서 필요한 연산을 효율적으로 수행하면서도 구현이 간단하고 메모리 오버헤드가 적기 때문에 더 적합한 선택이다.
