# [933. Number of Recent Calls](https://leetcode.com/problems/number-of-recent-calls/description/?envType=study-plan-v2&envId=leetcode-75)

## 문제 핵심 파악

`ping(t)`를 호출할 때마다, **`[t - 3000, t]` 범위 안에 있는 ping 횟수**를 반환한다.

### 버리는 조건

````
queue.peek() < t - 3000 → poll()
````


---

## 핵심 로직 재정리

1. 새 `ping(t)` 들어옴
2. `queue`에 추가
3. queue 앞에서 부터 `t - 3000`보다 작은 값들을 poll()
4. 남은 `queue`의 크기를 반환

````
        START: ping(t) called
                |
                v
    ┌─────────────────────────┐
    │ Add timestamp t to      │
    │ the back of queue       │
    │ queue.offer(t)          │
    └─────────────────────────┘
                |
                v
        ┌─────────────────┐
        │ queue.peek()    │
        │ < t - 3000 ?    │
        └─────────────────┘
             /      \
          YES        NO
           /          \
          v            v
┌─────────────────┐   ┌─────────────────────────┐
│ Remove oldest   │   │ Return queue size       │
│ timestamp        │   │ return queue.size()     │
│ queue.poll()     │   └─────────────────────────┘
└─────────────────┘                |
          |                        v
          └───────────────>  END
               repeat
````

---

## RecentCounter 동작 방식
각 `ping(t)` 호출은 **독립적**이다. queue는 호출 간에 유지된다.
````
ping(1)    호출 → queue에 1 추가, 결과 반환      → queue: [1]
ping(100)  호출 → queue에 100 추가, 결과 반환    → queue: [1, 100]
ping(3001) 호출 → queue에 3001 추가, 결과 반환   → queue: [1, 100, 3001]
ping(3002) 호출 → queue에 3002 추가, 결과 반환   → queue: [1, 100, 3001, 3002]   → queue: [100, 3001, 3002]
````

## 핵심
`queue.peek() < t-3000` 일 때만 제거하는데, t-3000이 음수면 queue 안의 값(최소 1 이상)이 항상 크거나 같아서 조건을 만족 못한다.<br>

**t-3000이 음수 → 제거 조건 불만족 → 아무것도 안 지워짐**

---

## My Solution
```
class RecentCounter {
    Queue<Integer> queue;

    public RecentCounter() {
        queue = new LinkedList<>();
    }

    public int ping(int t) {
        queue.offer(t);
        while (queue.peek() < t - 3000) {
            queue.poll();
        }
        return queue.size();
    }
}
```

---

## Review

로직 자체는 이미 최적이다. while로 범위 밖만 제거하고 size() 반환하는 구조는 시간복잡도 O(1) amortized, 공간복잡도는 O(n)가 된다.

###  Queue 인터페이스 타입 선언
필드는 `private`으로 캡슐화하는 게 좋다. 외부에서 직접 접근하면 안 된다.

````
// 현재
Queue<Integer> queue;

// 권장
private Queue<Integer> queue;
````

### 구현체 타입 선언 고려

````
// 현재
Queue<Integer> queue = new LinkedList<>();

// 최적화
Deque<Integer> queue = new ArrayDeque<>();
````

| 항목 | LinkedList | ArrayDeque |
|------|------------|-------------|
| 메모리 구조 | 노드마다 포인터 2개 | 배열 기반, 오버헤드 없음 |
| 캐시 효율 | 낮음 (포인터 따라 이동) | 높음 (연속된 메모리) |
| `peek()` / `poll()` | O(1) | O(1) (더 빠름) |

**시간복잡도**는 `O(1) amortized`, **공간복잡도** `O(n)`이 된다.

## O(1) amortized (분할 상환 O(1))
`amortized`는 **"평균적으로"** 라는 뜻이다.

### 왜 O(1)이 아니라 amortized O(1)일까?
ping(t)를 호출할 때마다 while루프가 돈다.

````
ping(3002) → poll() 1번  → O(1)
ping(5000) → poll() 3번  → O(3)  ← 얘만 보면 O(n)처럼 보임
ping(5001) → poll() 0번  → O(1)
````
한 번의 호출이 O(n)처럼 보일 수 있다.

### 근데 왜 amortized O(1)인가?
각 원소는 딱 한 번만 추가되고, 딱 한 번만 제거된다.

````
총 ping 호출 횟수: n번
총 offer 횟수:    n번
총 poll 횟수:     최대 n번
─────────────────────────
전체 연산 횟수:   최대 2n번 → O(n)

호출 1번당 평균: O(n) / n = O(1)
````

마치 월세처럼 어떤 달은 더 내고 어떤 달은 덜 내도, 1년 총합을 12로 나누면 **월평균은 일정**한 것과 같다.
