# [1137. N-th Tribonacci Number](https://leetcode.com/problems/n-th-tribonacci-number/submissions/2098043518/?envType=study-plan-v2&envId=leetcode-75)

## Intuition

The Tribonacci sequence follows the recurrence relation `Tn+3 = Tn + Tn+1 + Tn+2`, so we can use recursion to calculate `Tn`.

Memoization is used to store and reuse previously calculated values.

---

## Approach

1. Create a `memo` array of size `n + 3` and initialize it with `-1` to store calculated values.
2. If `n <= 0`, return `0`.
3. If `n <= 2`, return `1`.
4. Otherwise, recursively calculate `Tn` using `Tn = Tn-3 + Tn-2 + Tn-1`.
5. Store the calculated value in `memo` and return the stored value immediately if it has already been calculated.

---

## Complexity

### Time Complexity

**O(n)** — Each value is calculated only once using memoization.

### Space Complexity

**O(n)** — Both the `memo` array and the recursive call stack require O(n) space.

---

## My Solution

```java
import java.util.*;

class Solution {

    private int[] memo;

    public int tribonacci(int n) {
        memo = new int[n + 3];
        Arrays.fill(memo, -1);
        return calculate(n);
    }

    private int calculate(int n) {
        if (n <= 0) return 0;
        if (n <= 2) return 1;
        if (memo[n] != -1) return memo[n];

        memo[n] = calculate(n - 3) + calculate(n - 2) + calculate(n - 1);
        return memo[n];
    }
}
```

---

## Review

Memoization allows previously calculated values to be reused, resulting in **O(n)** time complexity.

However, for a simple linear recurrence like Tribonacci, an iterative approach is more efficient than recursion.

In the recursive approach, `calculate(n)` calls `calculate(n - 1)`, `calculate(n - 2)`, and `calculate(n - 3)`, which requires a recursive call stack. In the worst case, the stack depth can grow to `n`, resulting in **O(n)** additional space.

The iterative approach only needs the previous three values to calculate the next value. Therefore, we can maintain just three variables: `t0`, `t1`, and `t2`.

This reduces the space complexity from **O(n) to O(1)**.

---

## Improvements

* Recursion (top-down) → Iteration (bottom-up)
* `memo` array → Three variables
* Space complexity: `O(n)` → `O(1)`

---

## Revised Solution

```java
class Solution {
    public int tribonacci(int n) {
        if (n <= 0) return 0;
        if (n <= 2) return 1;

        int t0 = 0, t1 = 1, t2 = 1, next;

        for (int i = 3; i <= n; i++) {
            next = t0 + t1 + t2;
            t0 = t1;
            t1 = t2;
            t2 = next;
        }

        return t2;
    }
}
```

---

## Comparison Summary

|                     | Memoization (Top-down) | Iteration (Bottom-up) |
| ------------------- | ---------------------- | --------------------- |
| Time                | O(n)                   | O(n)                  |
| Space               | O(n)                   | O(1)                  |
| Function calls      | Recursive calls        | None                  |
| Stack overflow risk | Possible               | None                  |

## Performance Comparison

The actual LeetCode submission results showed similar performance for both solutions. However, runtime and memory measurements can vary depending on the execution environment, so the results alone do not necessarily mean that both approaches have the same performance.

The iterative version is theoretically more efficient.

* The memoization version uses both a `memo` array and a recursive call stack.
* The iterative version only keeps the previous three values and does not require an additional array or recursive calls.
* Both approaches have **O(n)** time complexity, but the space complexity is reduced from **O(n) to O(1)**.

### Key Improvements

**1. Recursion → Iteration**

Removed recursive calls to eliminate function call overhead and recursive stack usage.

**2. Array → Three Variables**

Since the next Tribonacci number only depends on the previous three values, the `memo` array can be replaced with `t0`, `t1`, and `t2`.

**3. Space Complexity**

* Original: **O(n)**
* Revised: **O(1)**

The time complexity remains the same, while the additional space is reduced from **O(n) to O(1)**.
