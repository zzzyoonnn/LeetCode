# [198. House Robber](https://leetcode.com/problems/house-robber/description/?envType=study-plan-v2&envId=leetcode-75)

## Intuition

We cannot rob two adjacent houses, but you can rob any number of non-adjacent houses.

To maximize the amount of money without triggering the alarm, we can use **memoization** to store the maximum amount that can be robbed from each position.

At each house, we have two choices: **rob the current house or skip it**. We then take the option that gives us the larger amount.

---

## Approach

1. Use a `memo` array to store the maximum amount that can be robbed starting from each index.
2. At each index, consider two cases:
   - **Rob the current house:** `nums[i] + solve(i + 2)`
   - **Skip the current house:** `solve(i + 1)`
3. Store the larger value in `memo[i]`.

---

## Complexity

### Time Complexity

**O(n)** — Each state is calculated only once, and previously calculated results are reused through memoization.

### Space Complexity

**O(n)** — The `memo` array requires O(n) space, and the recursive call stack can also grow up to O(n).

---

## My Solution

```
import java.util.*;

class Solution {
    private int[] memo;

    public int rob(int[] nums) {
        memo = new int[nums.length];
        Arrays.fill(memo, -1);
        return solve(nums, 0);
    }

    private int solve(int[] nums, int i) {
        if (i >= nums.length) return 0;
        if (memo[i] != -1) return memo[i];

        int rob = nums[i] + solve(nums, i + 2);
        int skip = solve(nums, i + 1);

        memo[i] = Math.max(rob, skip);
        return memo[i];
    }
}
```

---

## Review

Memoization achieves **O(n)** time complexity by avoiding repeated calculations.

However, each state only depends on the next two states:

```
dp[i] = max(nums[i] + dp[i + 2], dp[i + 1])
```

This means we do not actually need to store the result for every index.

Instead, we can calculate the states iteratively and keep track of only the two values needed to calculate the current state. This allows us to eliminate both the `memo` array and the recursive call stack, reducing the space complexity from **O(n) to O(1)**.

### Improvements

- Recursion (Top-down) → Iteration (Bottom-up)
- `memo` array + recursive call stack → Two variables
- Space Complexity: **O(n) → O(1)**

## Revised Solution

### Using DP Array

```
class Solution {
    public int rob(int[] nums) {
        int n = nums.length;
        if (n == 0) return 0;

        int[] dp = new int[n + 2];

        for (int i = n - 1; i >= 0; i--) {
            dp[i] = Math.max(nums[i] + dp[i + 2], dp[i + 1]);
        }

        return dp[0];
    }
}
```

This approach eliminates recursion and calculates all states using a DP array.

The time complexity remains **O(n)**, while the space complexity is **O(n)**.

### Using Two Variables

```
class Solution {
    public int rob(int[] nums) {
        int twoBack = 0;
        int oneBack = 0;

        for (int i = nums.length - 1; i >= 0; i--) {
            int current = Math.max(nums[i] + twoBack, oneBack);

            twoBack = oneBack;
            oneBack = current;
        }

        return oneBack;
    }
}
```

When calculating the current state, we only need the results from `i + 1` and `i + 2`.

Therefore, instead of maintaining the entire DP array, we can keep track of these two values using `oneBack` and `twoBack`.

This reduces the space complexity from **O(n) to O(1)**.

| Time                | O(n)                   | O(n)                  |

| Function calls      | Recursive calls        | None                  |

### Key Improvements

**1. Recursion → Iteration**

The recursive calls were replaced with an iterative approach, eliminating the recursive call stack and reducing function call overhead.

**2. Array → Two Variables**

The current state only depends on the results of the next two states. Therefore, the entire `memo` or `dp` array can be replaced with two variables.

**3. Space Complexity**

- Original: **O(n)**
- Revised: **O(1)**

Both approaches have the same **O(n) time complexity**, but the iterative solution eliminates the unnecessary array and recursive call stack, reducing the additional space complexity from **O(n) to O(1)**.
